# stage-5-operator-ui

## Причина

<!-- Why -->

Чернетки генеруються автоматично, але клієнт має отримати лише відповідь, яку переглянула людина.
Оператору потрібен простий веб-інтерфейс, щоб бачити звернення з чернетками, виправляти текст і підтверджувати або відхиляти відповідь — без ризику подвійної дії з двох вкладок.

## Що змінюється

<!-- What Changes -->

- `GET /ui` показує таблицю звернень із фільтром за статусом і автооновленням кожні 10 с.
- Картка звернення показує повідомлення клієнта, статті й редаговану чернетку з кнопками **Approve** і **Reject**.
- Approve зберігає фінальний текст і ключ ідемпотентності для надсилання; Reject закриває звернення; обидві дії спрацьовують лише для звернення в `draft_ready` і лише один раз.
- Якщо задано `OPERATOR_PASSWORD`, увесь `/ui` захищений HTTP Basic Auth.

## Функції

<!-- Features -->

### Нові функції

<!-- New features -->

- [`operator-ui`](/dev/specs/operator-ui/spec.md): список звернень із фільтром і автооновленням, картка звернення.
- [`moderation`](/dev/specs/moderation/spec.md): атомарне підтвердження й відхилення чернетки оператором.
- [`operator-auth`](/dev/specs/operator-auth/spec.md): опційний HTTP Basic Auth для інтерфейсу оператора.
